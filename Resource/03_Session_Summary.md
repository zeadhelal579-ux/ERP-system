# ملخص الجلسة — مراجعة وتصميم معماري لمشروع MES / Mini-ERP

**التاريخ:** 29 أغسطس 2026

---

## 1. الطلب الأصلي

مراجعة كاملة لمشروع ERP قائم (كل الملفات، كل كود الـ Backend)، ثم إعداد تصميم معماري شامل ومنظم ومفصّل (Backend + Frontend + Data)، قابل للتوسع، على الـ Stack التالي:
- **Backend:** C# / .NET
- **Frontend:** React + TypeScript + Tailwind CSS
- **Data:** SQL Server

مع تسليم 3 ملفات: التصميم المعماري، تقرير يشرح فكرة المشروع بالتفصيل، وتقرير بكل ما تم في هذه المحادثة.

## 3. أهم ما تم اكتشافه

### ما هو مبني فعليًا وبشكل سليم:
- Backend حقيقي وشغّال (ASP.NET Core 10 Web API)، ينفّذ نحو 85% من المواصفة الأصلية.
- بنية طبقية سليمة (Controllers → Services → Repositories → EF Core)، ومنطق آلة الحالات مطبّق بدقة في معظم المسارات.
- SQL Server هو قاعدة البيانات الفعلية بالفعل (وليس بديلًا مؤقتًا)، عبر EF Core Migrations.
- تشفير كلمات المرور وإصدار JWT يتمّان بطريقة آمنة وقياسية.
- Swagger/OpenAPI مُفعَّل بالفعل — أساس جاهز لتوليد أنواع TypeScript تلقائيًا للفرونت الجديد.

### الفجوة الأكبر:
**الفرونت غير مبني إطلاقًا حتى الآن** — الملفات الموجودة (`index.html`, `dashboard.html`, `lab.html`, `production.html`, `store.html`, `api.js`, `auth.js`, `main.css`) هي قوالب فارغة تلقائية بلا أي كود حقيقي. هذا في الواقع **يُسهّل المهمة**: لا يوجد كود قديم يُرحَّل، والبناء بـ React + TypeScript + Tailwind يبدأ من صفحة بيضاء تمامًا.

### مشاكل واكتُشفت بالمراجعة الدقيقة (موثّقة بالتفصيل مع الأولوية في `01_Architecture.md`، القسم 4.11):
1. 🔴 مفتاح توقيع الـ JWT مكتوب صراحة في `appsettings.json`، والملف غير مُستبعد فعليًا من الرفع لمستودع الكود (رغم أن `.gitignore` كان يهدف لذلك على ملف آخر بالخطأ).
2. 🔴 لا يوجد إعداد CORS إطلاقًا — سيمنع أي اتصال من فرونت React فور البدء.
3. 🟠 تعطيل إعادة التوجيه لـ HTTPS.
4. 🟠 حفظ مزدوج غير ضروري (`SaveChangesAsync` مرتين) في مسارين، يخالف مبدأ "العملية الذرية الواحدة".
5. 🟠 عدم وجود حماية من تعارض التزامن (Concurrency) عند خصم كميات المخزون.
6. 🟡 فجوة منطقية: قرار "الإعدام" لا يُحدِّث حالة التشغيلة نفسها، فقط سطر العزل — ما يُضخِّم عداد "العزل" في لوحة المدير العام.
7. 🟡 غياب فهارس Unique على اسم المستخدم ورقم التشغيلة على مستوى قاعدة البيانات.
8. 🟡 هالك خط الإنتاج لا يُسجَّل كسطر في جدول الهالك المركزي، خلافًا لنص المتطلبات صراحة.
9. 🟢 ملاحظات أصغر: تحذير أمني مُسكَت في NuGet، ملف AutoMapper فارغ غير مُستخدم، تكرار كود بسيط في الـ Controllers، استخدام توقيت محلي بدل UTC.

## 4. القرارات المعمارية الرئيسية في التصميم المُسلَّم

- الإبقاء على نفس البنية الطبقية الحالية للـ Backend وتقويتها (وليس إعادة كتابتها من الصفر) — لأنها بنية سليمة أصلًا.
- توسعة قاعدة البيانات لدعم وصفة تصنيع متعددة المكونات (BOM) بدل الاقتصار على خامة واحدة لكل تشغيلة.
- تطبيع بيانات الموردين والعملاء بدل حقول النص الحر.
- إعادة هيكلة جدول الـ Audit ليطابق الحقول المنصوص عليها أصلًا في المتطلبات.
- غلاف استجابة API موحّد (`ApiResponse<T>`) لتسهيل التكامل مع فرونت TypeScript.
- توليد أنواع TypeScript تلقائيًا من Swagger بدل كتابتها يدويًا.
- بنية فرونت React مقسّمة حسب الميزة (Feature-based)، بشاشة مستقلة لكل قسم من أقسام المصنع السبعة، مطابقة تمامًا للأدوار الفعلية في الكود.
- خارطة طريق تنفيذ من 6 مراحل (Phase 0 إلى Phase 5)، تبدأ بتحصين الأمان قبل أي عمل فرونت.
